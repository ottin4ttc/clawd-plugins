# clawd

两个 tool：`login`、`share_file`（`mcp__clawd__*`）。

## 分享

**链接要飞书登录才能打开，公司内任何登录用户都能看**，永久有效。调 `share_file` 之前：

1. 看文件名和用户描述，判断是不是敏感内容——密码、密钥、合同、客户名单、身份证、财务数据、带个人信息的表格。是 → **不调**，告诉用户这类内容不该分享；用户坚持也先让他确认内容里没有敏感信息
2. 跟用户说一句：「链接需要飞书登录，公司内任何人登录后都能看，确认 xxx 没有敏感信息我就发」

`share_file` 传绝对路径，文件和文件夹都行：

- 文件夹 = 静态站点：有 `index.html` 就是首页，没有就出文件列表；`.` 开头的文件和 `node_modules` 不上传；上限 100 MB / 500 个文件
- `.md` 打开时渲染成页面；图片、pdf 直接看
- 凭据形态的文件名（`.env`、`*.pem`、`*.key`、`id_rsa` 等）直接拒绝——文件夹里有一个就整个拒

Codex 会再弹一次审批，正常。

返回：
- `{ url, warning }` → 把 `url` 给用户，并把 `warning` 那句带上。不附本地路径
- `{ status: "login_required" }` → 先 `login`，再调一次 `share_file`
- 报错 → 照实转述。「分享未配置」= 服务端没开分享，让用户找管理员

## 登录

`login` 无参数，会打开浏览器（飞书扫码）并**等到登完才返回**。调之前先说一句「浏览器已打开，请完成登录」。

- 已登录 → 立刻返回 `{ loggedIn: true, displayName }`，念给用户「已登录：<名字>」
- 「登录超时」→ 用户没在浏览器完成；可再说一次「登录」或打开返回里的链接
- 「登录失败：…」→ 照实转述，不猜

同一台电脑上 Codex 和 clawd 桌面端共用这次登录。

## 不要

- 把 `file://` 路径当链接发给用户
- 自己读文件内容贴给用户代替分享
- 读 `~/.clawd/` 判断登录状态——调 `login` 就是判断
- 让用户手动复制粘贴任何 token
